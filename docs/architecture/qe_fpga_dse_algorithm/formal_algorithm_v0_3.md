# Formal Algorithm v0.3: Workflow-Mismatch-Aware Multi-Fidelity DSE

Status: current formal algorithm after iterations 1-4, with the first
executable v0.3.1 contract captured in Section 11.

## 1. Objects

For a workload `w`, build a typed workflow graph:

```text
G_w = (V_s, V_c, V_d, E_ctrl, E_data, E_art, E_reuse)
```

where:

- `V_s` are QE workflow stages;
- `V_c` are compute regions or kernel callsites;
- `V_d` are data/artifact objects;
- `E_ctrl` are control and ordering constraints;
- `E_data` are dataflow edges;
- `E_art` are file/artifact dependencies;
- `E_reuse` are restart, persistence, and reuse edges.

The deployment candidate space is generated by grammar `Gamma`:

```text
X_w = Gamma(G_w, A, M, S, R, P)
```

where:

- `A` is the architecture-template set;
- `M` is the mapping/offload-boundary grammar;
- `S` is the scheduling grammar;
- `R` is the residency/memory grammar;
- `P` is the implementation/precision grammar.

The fidelity ladder is:

```text
F = {L0, L1, L2, L3, L4, L5}
```

from legality checks through analytical models, TLM/SystemC-like models,
generic-sim/gem5/SystemC, HLS/RTL, and Vivado/bitstream/board feedback.

## 2. Objective Vector

All objectives are minimized:

```text
y_f(x,w) = [
  latency_ms,
  energy_mj,
  edp,
  resource_pressure,
  data_movement_mb,
  implementation_risk
]
```

A candidate is final-claim eligible only if the claim-specific correctness and
tool gates are satisfied.  Model-level objectives are projections and can guide
search, but they do not prove hardware performance.

## 3. Workflow-Mismatch Vector

The central algorithmic signal is:

```text
phi_m(G_w, x) = [
  host_control_pressure,
  artifact_lifetime_pressure,
  transfer_sync_pressure,
  post_processing_fanout,
  branch_restart_reuse_sensitivity,
  resource_cliff_risk,
  correctness_pressure,
  implementation_handoff_risk
]
```

`phi_m` estimates where cheap models are likely to mis-rank candidates because
they ignore workflow-level control, persistence, synchronization, correctness,
or implementation constraints.

The rank-inversion event is:

```text
I_f(x_i, x_j, w) =
  1 if rank_L1(x_i, x_j, w) != rank_f(x_i, x_j, w)
  0 otherwise
```

The mismatch model estimates:

```text
p_m(x,w) = Pr[ candidate x is misranked by L1 | phi_m(G_w,x), phi_x ]
```

where `phi_x` are candidate grammar features.

## 4. Residual Surrogate

For each fidelity `f > L1`, learn residual objectives:

```text
r_f(x,w) = log(y_f(x,w)) - log(y_L1(x,w))
```

The posterior returns:

```text
M_t(x,f,w) -> (mu_f(x,w), Sigma_f(x,w), p_feas(x,w), p_m(x,w))
```

where:

- `mu_f` is the residual-corrected objective prediction;
- `Sigma_f` is predictive uncertainty;
- `p_feas` is feasibility probability;
- `p_m` is cheap-model mismatch probability.

The model may be a calibrated ensemble, graph surrogate, GP residual model, or
hybrid.  The first implementation can be simpler, but the method definition
requires uncertainty and feasibility estimates.

## 5. Candidate-Fidelity Acquisition

At iteration `t`, the action is:

```text
a_t = (x_t, f_t)
```

not just a candidate.  The acquisition is:

```text
A_t(x,f) =
  p_feas(x,w)
  * [
      EHVI_t(x)
      + lambda_u U_t(x)
      + lambda_m p_m(x,w) V_m(x,w)
      + lambda_d D_t(x)
    ]
  * VOI_t(f | x,w)
  / C_t(x,f)
```

Definitions:

- `EHVI_t(x)`: expected hypervolume improvement against the current frontier.
- `U_t(x)`: calibrated uncertainty value.
- `p_m(x,w) V_m(x,w)`: mispromotion-avoidance value from workflow mismatch.
- `D_t(x)`: design diversity value.
- `VOI_t(f | x,w)`: value of information for the chosen fidelity.
- `C_t(x,f)`: candidate/fidelity evaluation cost.

The fidelity value is:

```text
VOI_t(f | x,w) =
  alpha_h * expected_frontier_information_gain
  + alpha_c * expected_calibration_reuse
  + alpha_g * expected_gate_resolution
  - alpha_r * prerequisite_risk
```

This replaces fixed fidelity metadata with a measurable estimate of what the
next observation will teach the search.

## 6. Update Rule

After observing `z_t = observe(x_t, f_t, w)`:

```text
T_{t+1} = T_t union {z_t}
M_{t+1} = update_posterior(M_t, z_t)
Cal_{t+1} = update_fidelity_calibration(Cal_t, z_t)
P_{t+1} = update_pareto_estimate(P_t, M_{t+1})
Gamma_{t+1} = optional_update_candidate_generator(Gamma_t, z_t)
```

The update must preserve blocker semantics.  A failed HLS/Vivado gate is not a
missing value; it is feasibility feedback.

## 7. Algorithm

```text
Algorithm WAMF-DSE-v0.3

Input:
  workflow corpus W
  deployment grammar Gamma
  fidelity ladder F
  budget B

Output:
  Pareto set P
  trace T
  calibrated model M
  implementation handoff H

1. T <- empty
2. For each workload w in W:
     G_w <- build_typed_workflow_graph(w)
     Phi_w <- extract_workflow_mismatch_features(G_w)
     X_w <- Gamma(G_w)
     X_w <- legality_filter(X_w)
     Evaluate L1 for broad X_w

3. Initialize posterior M from L1 projections and any seed observations.

4. while budget remains:
     A <- empty
     for each workload w:
       for each admissible candidate x in X_w:
         for each admissible next fidelity f in F:
           if prerequisites(x,f) are not satisfied:
             continue
           score <- acquisition A_t(x,f)
           A <- A union {(x,f,score)}

     if A is empty:
       stop with blockers

     (x_t, f_t) <- argmax score in A
     z_t <- observe_or_request(x_t, f_t)
     T <- T union {z_t}
     M <- update_posterior(M, z_t)
     update calibration, frontier, blockers, and candidate neighborhoods

5. P <- extract_pareto_candidates(M, T)
6. H <- generate_implementation_handoff(P subject to feasibility gates)
7. return P, T, M, H
```

## 8. Baseline And Ablation Protocol

The method must be compared under the same expensive-evaluation budget against:

- random legal candidate selection;
- manual HBM streaming heuristic;
- L1-only EDP/Pareto ranking;
- kernel-hotspot-only ranking;
- SCF-only or single-stage abstraction;
- NSGA-II/III over L1 objective vectors;
- BO/EI or surrogate EI over flattened candidates;
- Hyperband/successive halving;
- WAMF without workflow mismatch;
- WAMF without uncertainty;
- WAMF without calibration;
- WAMF without implementation-risk modeling.

Each baseline must report:

- selected candidate/fidelity trace;
- best objective versus budget;
- top-k hit;
- simple regret;
- constrained hypervolume;
- promotion precision/recall;
- mispromotion rate;
- rank correlation against independent fidelity.

## 9. Distinction From Prior DSE Patterns

- MAESTRO, Timeloop, and ZigZag show that structured architecture/mapping
  representations and cheap analytical models can explore enormous spaces.  This
  method uses the same lesson but moves the representation boundary to
  scientific workflow deployment: cross-stage host control, data persistence,
  restart/reuse, offload boundary, and implementation feasibility.
- NSGA-II/III provides generic Pareto search.  This method must show that
  workflow-mismatch features improve promotion under a scarce high-fidelity
  budget.
- BO/HLS tuning handles expensive black-box optimization after a design space is
  defined.  This method adds workflow-derived candidate generation and
  candidate/fidelity action selection across heterogeneous evidence gates.
- QE GPU ports optimize a concrete implementation.  This method searches
  deployment options and preserves host/control/data movement in accounting.

## 10. Completion Boundary

`WAMF-DSE-v0.3` is complete as an algorithm definition when:

- workflow mismatch features are defined and extracted;
- candidate grammar and fidelity ladder are explicit;
- acquisition uses posterior uncertainty, feasibility, mismatch, and VOI;
- baselines and ablations are defined;
- evidence levels are separated from final hardware claims.

It is complete as a DAC result only after independent evidence demonstrates
that workflow-mismatch-aware promotion improves sample efficiency and avoids
mispromotion under realistic QE workflow conditions.

## 11. First Executable Contract For v0.3.1

The first implementation should be deliberately conservative.  It should prove
that the workflow-mismatch idea changes promotion decisions before using a
larger neural model or chasing bitstreams.

### Feature Contract

For each `(w, x)` build:

```text
z(w,x) = [
  phi_w(G_w),
  phi_x(x),
  phi_m(G_w,x),
  interactions(phi_w, phi_x)
]
```

where all entries must be replayable from the workflow fixture, candidate
grammar, and fidelity trace.  `phi_m` is not an opaque neural embedding in the
first implementation; it is a measurable vector containing host-control,
artifact-lifetime, transfer/sync, branch/reuse, post-processing, resource-risk,
correctness-pressure, and implementation-handoff features.

### Residual Objective Model

For `f > L1`, train residual predictors:

```text
delta_f(x,w) = log(y_f(x,w) + eps) - log(y_L1(x,w) + eps)
```

The first valid model families are:

- bootstrapped ridge/random-forest/gradient-boosted residual regressors over
  engineered features;
- Gaussian-process residual models when labels are very small;
- small MLP ensembles with conformal calibration when enough labels exist.

Graph neural surrogates are a later extension, not the first proof.

### Mispromotion Model

Define constrained Pareto usefulness under fidelity `f`:

```text
useful_f(x,w) =
  feasible_f(x,w)
  and (
    x is in top-k_f
    or x contributes positive constrained hypervolume
    or x is within tau regret of the best observed feasible point
  )
```

For an L1-promoted or L1-high-ranked candidate, define the mispromotion label:

```text
ell_m(x,w,f) = 1 if promoted_by_L1(x,w) and not useful_f(x,w)
               0 otherwise
```

Then:

```text
p_m(x,w) = CalibratedPr[ell_m = 1 | z(w,x)]
```

The first implementation may use a bootstrapped logistic classifier or calibrated
tree ensemble.  It must report calibration error and uncertainty; an uncalibrated
score is only a ranking feature, not `p_m`.

### VOI Contract

The first executable `VOI_t(f | x,w)` should be:

```text
VOI_t(f | x,w) =
  beta_h * E[frontier information gain]
  + beta_c * E[calibration reuse over N_k(x,w)]
  + beta_g * E[gate resolution value]
  - beta_r * prerequisite/tool risk
```

where:

- frontier information gain is estimated from posterior samples and constrained
  hypervolume or top-k change;
- calibration reuse sums similarity-weighted expected residual/feasibility
  entropy reduction over candidate neighbors `N_k(x,w)`;
- gate resolution value is the expected reduction in feasibility uncertainty for
  HLS/Vivado/tool prerequisites;
- prerequisite/tool risk is a deterministic blocker or historical failure-cost
  penalty.

If the implementation cannot estimate a term from data, it must either set the
term to zero with a blocker reason or run the deterministic WAMF baseline.  It
must not silently replace VOI with a hand-tuned constant while calling the result
posterior-driven active search.

### Sparse-Label Update

After observing `z_t = observe(x_t, f_t, w)`:

```text
1. append the raw observation and blocker state to T
2. update residual labels delta_f if objectives are observed
3. update feasibility labels if a gate passed or failed
4. update ell_m labels for any candidate whose usefulness can now be judged
5. refit or incrementally update residual, feasibility, and mispromotion models
6. recompute calibration error, posterior intervals, and frontier estimate
```

Tool failure is a feasibility observation, not a missing value.

### Minimum Closed-Loop Experiment

Before claiming algorithm superiority, run the same fixed candidate pools and
budgets for:

- WAMF-DSE v0.3.1;
- WAMF without workflow-mismatch features;
- L1-only EDP/Pareto;
- kernel-hotspot-only;
- SCF-only or single-stage abstraction;
- random legal candidate selection.

The first budget schedule should include at least `2`, `4`, and `8` independent
high-fidelity observations per workload class.  Report promotion precision,
mispromotion rate, simple regret, constrained hypervolume, top-k hit, rank
correlation, calibration error, and bootstrap confidence intervals.
