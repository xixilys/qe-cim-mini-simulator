# DFT Architecture Family Research Notes

Status: implementation reference for the DFT-first Step2 architecture-candidate lane.  
Scope: external-source-derived architecture taxonomy for DFT/electronic-structure workloads.  
Claim boundary: the taxonomy provides candidate facts, patterns, and Step3 timing-model assumptions; it is not a universal hardware-optimality claim and does not assert numerical correctness.

## Method

The search intentionally started outside the repository, then mapped recurring external patterns back to the generic catalog contract.  A family is kept only when it maps to at least one DFT phase/kernel class and can be represented with domain-neutral components, ops, memory, interconnect, and evidence labels.  When a family cannot be made Step3-searchable, the blocker must identify a missing workload fact, missing timing primitive, required RTL/HLS/IP detail, missing memory/interconnect/resource model, or a false-claim risk.

## Taxonomy and searchability decisions

| Architecture family | Matched DFT phases/kernels | Hardware pattern | Searchable parameters | Step3 decision | Blockers / limits |
| --- | --- | --- | --- | --- | --- |
| CPU-only baseline | all phases as host fallback | multi-core host DRAM | cores, host bandwidth, clock, memory capacity | Step3-searchable baseline | not an accelerator winner; final claims need real CPU calibration. |
| FPGA-HBM streaming | FFT, grid, density, local potential, reductions, ERI streaming when present | host + FPGA fabric + HBM + DMA | HBM bandwidth/capacity, stream lane count, DMA bandwidth, FPGA clock | Step3-searchable with generic FFT/reduction/stream ops | corner-turning, bank conflicts, and II are simplified. |
| FPGA FFT/grid-heavy | FFT/rho/grid transpose-heavy phases | host + FPGA FFT pipeline + HBM/BRAM | FFT pipelines, HBM channels, transpose penalty, local buffer | Step3-searchable with FFT/stencil/stream ops | no explicit 3D corner-turn primitive yet. |
| FPGA systolic GEMM | h_psi, subspace rotation, exact exchange block GEMM, dense phases | host + FPGA systolic fabric + local/HBM buffers | PE array scale, GEMM efficiency, memory capacity, clock | Step3-searchable with GEMM/batched_GEMM ops | actual tiling/reuse model is simplified. |
| FPGA+GPU diagonalization hybrid | diagonalization/eigensolver, dense linear algebra, GPU-strong stages with FPGA streaming support | host + GPU + FPGA + HBM/interconnect | GPU/FPGA op split, interconnect bandwidth, eigensolver efficiency | Step3-searchable with GPU/FPGA ops | Step3 mapping remains heuristic; no real multi-GPU collective model. |
| Memory-rich HBM | memory-bound FFT/grid/reduction/sparse-matrix phases | host + FPGA + multiple HBM/local memory components | HBM bandwidth/capacity, memory hierarchy capacity, transfer policy | Step3-searchable as a generic memory-rich template | HBM bank conflicts and cache reuse are summarized only. |
| Low-power FPGA | energy-constrained DFT subsets, small/medium FFT/GEMM/reduction | host + lower-power FPGA fabric, fewer lanes, constrained power | power cap, frequency, supported ops, memory | Step3-searchable as a lower-power bound | lower throughput estimates are conservative; no voltage/frequency model. |
| Custom FPGA/ASIC / LS3DF | reformulated LS3DF, domain-specific kernels | custom accelerator, possibly FPGA then ASIC | unavailable until kernel semantics and RTL/HLS/resource facts exist | candidate-only unless a concrete binding is supplied | would otherwise create false timing precision. |

## Implementation mapping

The repository catalog now encodes the Step3-searchable families as concrete instances with `standalone_generic_systemc_v1` bindings and `trusted_final_claim=false` downstream.  The model is intentionally generic: components expose supported ops and memory/interconnect facts; DFT-specific phase matching remains in `dse_v2/reference_workloads/dft_step2_policy.py`.

Minimum instances expected by this research note:

- `dft-cpu-baseline-v0`
- `dft-fpga-hbm-streaming-v0`
- `dft-fpga-fft-grid-v0`
- `dft-fpga-systolic-gemm-v0`
- `dft-fpga-gpu-diag-hybrid-v0`
- `dft-memory-rich-hbm-v0`
- `dft-low-power-fpga-v0`

All Step3-searchable instances are simplifications.  They may rank candidates within a requested run, but cannot establish a universal best architecture without workload-specific profiles, measured calibration, and higher-fidelity validation.
